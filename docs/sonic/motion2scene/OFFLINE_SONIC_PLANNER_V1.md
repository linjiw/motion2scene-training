# Installed SONIC planner: one CPU reference proposal

The installed planner produced one unqualified slow-walk reference from the
qualified neutral reference's **planned future context**. This establishes a
working file-only input/output bridge. It does not establish physical tracking,
height-conditioned walking, longer traversal, or repeated adaptation.

The immutable registration and result are in:

```
/home/linjiw/research-data/groot-wbc/m2s-sonic-planner-cpu-parity-v1/
```

`manifest.json` was written before the attempt and binds the model, qualified
source, recorded reference, loaded bank, all eleven input tensors, context
timestamps, joint-limit XML, implementation files and CPU package versions.
Its SHA-256 is
`30503e42c237403259dc3fb7bf1ede4b0460e42eb1d96669ec8e70a2fcc3b970`.
Output filenames and their schema were preregistered; their actual hashes were
recorded afterward in `result.json`, because generated bytes are unknown before
inference. `attempt.json` is an exclusive marker: the CLI rejects a second run
under the same registration. The original registration and artifacts are retained.

## Contract and implementation

- [Pure adapter](../../gear_sonic/dataset_generation/hallucination/motion2scene_planner_adapter.py):
  exact named 29-joint permutation, WXYZ quaternions, planned-context sampling,
  eleven input shapes/dtypes, int32 valid count, token-mask checks and diagnostics.
- [File-only CLI](../../scripts/research/motion2scene_offline_planner.py):
  separate `prepare` and `run`, source/environment checks, explicit CPU provider,
  one inference call and native-rate exports. It imports no robot or simulator.
- [Focused tests](../../decoupled_wbc/tests/test_motion2scene_planner_adapter.py):
  12 tests cover joint identity, interpolation and quaternion sign equivalence,
  endpoint rejection, input types/modes, output counts, invalid values and joint
  limits without silently clipping the candidate.

The neutral reference is source41002 from the existing development bank. Its
recorded reference XYZ and joint positions match loaded bank index0 exactly at
all199 reference samples. The recorder explicitly names the Isaac Lab joints and
WXYZ quaternion convention; the adapter permutes joints by name into MuJoCo order.
No actual robot state is substituted for the planned reference in this experiment.

At current frame15 of the50Hz reference, context sampling begins two ticks later:
0.34, 0.3733333333, 0.4066666667 and0.44s. Position and joint interpolation is linear;
rotation uses shortest-arc quaternion slerp. The offline gate rejects an unavailable
future endpoint instead of copying its last pose. This follows the deployed
`UpdateContextFromMotion` timing for an interior reference window.

The registered controls are mode1 (`SLOW_WALK` in the common C++ enum), target
speed0.6m/s, height−1 (mode default), seed1234 and world movement/facing directions
equal to the first context yaw. Specific target keyframes are disabled. The active
TensorRT wrapper's mask allows36,40 or44 frames. The offline adapter deliberately
accepts only the audited common modes0,1,2 and4; only mode1 was sampled here.
Neither nonpositive speed nor an idle mode is treated as a verified protective stop.

The output remains at30Hz. `raw_outputs.npz` preserves the complete1×64×36 graph
array and its int32 count. `candidate_30hz.csv` contains only valid XYZ/WXYZ/29-joint
frames. `candidate_30hz.pkl` uses the existing SONIC conversion at30Hz, preserving
world position and using that format's XYZW `root_rot`. Its `smpl_joints` array is a
compatibility placeholder, not SMPL supervision. No clip is padded, blended,
retimed, joined to the neutral, or physically executed by this CLI.

These times describe one local CPU call, not a runtime benchmark or a deployment
latency guarantee. All valid output values are finite. The first four generated
frames approximately reconstruct the supplied context; they are not exact copies.
The joint discrepancy and subsequent0.094797rad context-to-new-frame step must be
accounted for when designing a physical continuation. Static MJCF range checks do
not test collisions, dynamics, contacts, stability or executable transitions.

The result supplies a1.17s proposal, not a longer motion than the existing4s carrier.
It is not compatible with the current equal-duration199-frame online option bank.
The Python reference loader and C++ planner resampler have different endpoint
conventions: this36-frame source is expected to yield59 samples in the Python
exclusive-end loader, whereas the C++ planner path emits60 samples and may briefly
hold the final endpoint. A future replay must record the actual loaded bank and
bound capture before reference resampling/reset; do not resample this30Hz output
twice or assume the old199-frame budget.

## Reproduction and next qualification gate

The isolated `.venv_planner_cpu` environment contains CPU `onnxruntime==1.29.0`,
`numpy==2.4.6`, `scipy==1.17.1`, `joblib==1.6.0` and `onnx==1.22.0` under Python3.11.16.
No shared Kimodo/Isaac environment was changed. ONNX Runtime documents the CPU
package separately from its GPU distribution in its
[installation instructions](https://onnxruntime.ai/docs/install/).

Use a **fresh** output directory for a new registration. The implemented CLI is:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
.venv_planner_cpu/bin/python scripts/research/motion2scene_offline_planner.py prepare \
  --out /absolute/path/to/fresh-development-proposal \
  --model /absolute/path/to/planner_sonic.onnx \
  --registry /home/linjiw/research-data/groot-wbc/m2s-online-option-registry-v1/registry.json \
  --joint-limits /home/linjiw/kimodo/kimodo/assets/skeletons/g1skel34/xml/g1.xml \
  --current-frame 15 --mode 1 --speed 0.6 --height -1 --seed 1234

CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
.venv_planner_cpu/bin/python scripts/research/motion2scene_offline_planner.py run \
  --manifest /absolute/path/to/fresh-development-proposal/manifest.json
```

The next gate is a separately registered continuation proposal with an explicit
source anchor, quaternion/joint join and finite horizon. The deployed wrapper's
eight-frame50Hz blending is a possible reference construction rule, not evidence
of an executable join. First replay the candidate/continuation in a fresh empty
development corridor with the frozen tracker; record initial stabilization,
executed envelope, contact, fall and reference exhaustion. Then qualify the join
from a matched approach state before exposing it as a high-level option.

A height-conditioned mode4 sample would test the actual installed squat interface
and needs its own registration and physical outcome. Longer behavior requires
qualified planning continuation or a genuinely longer generated carrier. An
achieved-history context is also a separate experiment: its four samples end at
the decision time, its output anchor is0.10s earlier, and its first four generated
frames overlap history. This adapter does not currently accept that changed input
distribution or count those history frames as future progress.
