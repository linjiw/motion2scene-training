# Verified physical-gap replay for 114D schedules

The [pre-adoption rule amendment](/home/linjiw/research-data/groot-wbc/m2s-primary-replay-fallback-amendment-proposed-v2/amendment.json) explicitly selects the implemented behavior over the proposed plan’s pure-uniform fallback prose: when no supervised encounter has a positive verified gap, only the 0.6 gap component becomes uniform. The complete mixture remains **0.8 uniform + 0.2 coverage**. For three single-phase encounters in bins `(shared, shared, rare)`, it assigns masses `(19/60, 19/60, 22/60)`. The code, frozen rule, candidate assignments and budgets are unchanged; the amendment will be bound by the separate primary adoption.

The [offline CLI](../../scripts/research/motion2scene_build_timed_replay.py) and [pure weighting module](../../gear_sonic/dataset_generation/hallucination/motion2scene_timed_schedule_curriculum.py) write evidence and replay weights from recorded development episodes. They perform no training, simulation or geometry search. This is an implemented component, not a measured curriculum result.

The CLI independently re-audits the generic schedule trainer's `teachers.json` against its registered physical collections. For each student collection it checks the actual invocation, scene asset, physics seed, option registry, model identity, sensor schema, artifacts, physical outcome and measured passage time. Default operation requires one frozen student model. Different runtime dependency identities receive no matched-gap credit. Reserved evaluation records cannot enter this training-data workflow.

At each actually visited neutral decision phase, `history_id` binds the complete recorded physical prefix and causal preaction sensor/state history. The current postdecision action is excluded. The current 114D features and legality mask must match exactly too. This is agreement of recorded history, not a claim that unrecorded simulator or controller hidden state was restored.

The teacher must have a complete admitted legal-action table and a verified passing continuation. WAIT refers to the best complete future schedule, not forced walking. A student's actual failure has gap 1; if both teacher and student pass, the gap is `max(0, (student_time - teacher_time) / max(student_time, teacher_time, 1e-12))`. Predicted values, BCE, selected-action labels and outcome lookup supply no physical gap. Missing, unobservable or unmatched evidence has unknown gap, not a high-loss priority. A verified early physical failure may retain earlier available supervision even if later packets are unavailable; an unbound partial capture cannot establish a matched gap.

The default observation rule requires actual beam-surface evidence delivered by the **current** decision state, with a declared nonnegative sensing margin. It checks every collision-enabled beam. Empty scenes require no obstacle cue. Underside evidence is a separately selectable rule. The receipt also records cue availability at the teacher continuation's later entry, but future visibility never becomes a current input. There is no inferred common-safe-WAIT override, semantic recognition guarantee, or claim that this visibility check alone proves the full transition timing inequality.

Replay uses **0.2 uniform + 0.2 declared coverage + 0.6 verified physical gap**. Coverage keys contain the teacher's complete continuation reference, obstacle-length bins, current decision phase, and continuation entry/return ticks. Geometry is privileged sampling metadata and is never appended to student inputs. Each scene/seed encounter is normalized before distributing mass to complete feasible phase targets, so three WAIT visits do not triple encounter mass. An encounter's gap is its maximum eligible matched phase gap. If there are no positive verified gaps, the 0.6 term is explicitly reported as uniform fallback; its regret-priority component remains zero. Unavailable target rows remain in evidence with zero training weight.

All original capture paths are resolved before counting physical steps. One capture appearing in both teacher and student evidence is counted once; distinct actual captures with identical deterministic bytes remain distinct. Unknown startup or missing-recording costs are listed separately and are not inferred from packet counts.

```bash
.venv_isaaclab/bin/python scripts/research/motion2scene_build_timed_replay.py \
  --teachers /path/to/registered_training/teachers.json \
  --student-results /path/to/actual_student_collection/result.json \
  --out /path/to/new_replay_receipt
```

The output directory must be new. `registration.json` freezes the source closure and input hashes before re-audit; `evidence.json` records gap/admission reasons and accounting; `weights.json` maps weights to exact teacher collection, phase and recorded-history identities. Default rules are registered with each run; `--rule` accepts an explicit compatible rule JSON. No real replay-weight acquisition run or downstream gain is claimed by the synthetic tests.

The optional `--acquisition-receipt` mode accepts an explicitly adopted ordered acquisition prefix. The [plan validator](../../gear_sonic/dataset_generation/hallucination/motion2scene_acquisition_plan.py) binds the bootstrap and completed rounds to pre-update model commitments and teacher-release receipts. The replay reader additionally verifies that each executed model's training collections are exactly the bootstrap plus strictly earlier rounds, with the same re-audited targets and capture identities. It reports each gap's generating model, training result, penalty and age in completed rounds. A proposed plan cannot enable this path. The default still rejects multiple model hashes. Historical gaps are not errors of the final model; file commitments are not an independent attestation of dispatch chronology.

The trainer-facing `verify_weights(weights_path, groups, registry_ref)` independently rebuilds all evidence from the bound physical inputs and compares every gap, component mass, capture count and target identity. It returns `weights_in_group_target_order`, including explicit zero weights for unavailable phase slots, plus aligned rows and an audit summary. It writes no temporary snapshots, trains no model and runs no physics. Import this API lazily inside the trainer to avoid a reciprocal module-import cycle. Rehashing edited evidence or changing a weight does not bypass physical recomputation.

The distribution report contains minimum positive and maximum weights, their ratio, effective sample size and each mixture component's total mass. These describe what changed in replay; they do not show that a nearly interpolating learner changes its decisions or improves. That requires an actual controlled fit and execution comparison. Forty focused tests cover physical-gap semantics, future-versus-current cues, missing supervision, source/invocation changes, weight tampering and ordered model provenance.

The finite one-entry bank may already contain every subsequently visited neutral prefix; this workflow does not itself establish that DAgger added new states. No real acquisition receipt or curriculum-performance result is claimed by this component implementation.
