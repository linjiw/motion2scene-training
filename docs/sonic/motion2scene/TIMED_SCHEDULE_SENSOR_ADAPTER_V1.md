# Repeated commitment adapter for qualified finite schedules

This opt-in implementation passed its first physical runtime smoke: a forced late short schedule on the existing short development beam. The immutable `m2s-timed-schedule-smoke-v1` receipt records 298 synchronized control packets, 1,192 physics steps, exact 114D replay, entry at 1.40 s, return at 5.30 s, and 4.04 s passage. Two further development integration smokes also passed: the sensor script waited at ticks15/50 and selected short at70 (4.04s passage), and a forced prior schedule entered at50 and crossed both beams in order (4.12s course passage). Both retained298 exact-replayed114D packets,1,192 physics steps, zero measured undesired environment contact, and return265. The second-beam stream is a distinct native column for all30 bodies. These results establish implementation on the two development layouts, not learned generalization or repeated adaptation. It does not promote an experimental motion request to an online option bank. Every mode, including forced data acquisition, requires `load_verified_registry` to verify the complete reference/controller/evidence artifacts. The current three-option, 106D adapter and its nine executed development episodes remain separate and unchanged.

The new runtime is `gear_sonic.dataset_generation.hallucination.motion2scene_timed_schedule_execution.TimedScheduleEnvCfg` with `TimedScheduleRecorderCfg`. The low-level tracker and the guarded motion-library switch are inherited. The new hooks supply sensor history and request one complete schedule; they do not alter joint targets, reset state, extend the reference, learn a return action, or permit a second adaptation. An entry at a later qualified phase is another opportunity to commit. Identical references may produce identical executions after early and late commitments; the interface alone establishes no improved physical timing.

`motion2scene_timed_schedule_policy.py` derives decision phases and option IDs from the verified bank. With seven complete schedules, the input has exactly 114 named values: the existing 100 sensor/state/phase features, seven preaction active-option indicators, and seven measured legality indicators. Observation uses the same ideal PhysX 65-ray fan and surface normals, accumulated causally for at most 2.0 seconds or 101 frames. This differs from the 106D adapter's 0.5-second/26-frame memory and must be controlled separately in comparisons. Floor and ceiling retain independent observed/unknown masks. Scene IDs, beam parameters, physical outcome labels, and privileged teacher state are absent from policy inputs.

Modes are `always_walk`, `constant_option`, `scripted_reference`, `scripted_multi`, `learned`, and `forced`. A constant option names an exact complete schedule and waits until that entry is legal. The scripted reference uses measured upper occupancy and selects a currently legal schedule for its named reference. The multi-option script uses the same named corridor features to choose currently legal prior, short, or sustained schedules. Its explicit JSON settings are SHA-bound through `--script-parameters`; single-action holds and mandatory return bypass the script. These provisional development thresholds are not geometric guarantees. The learned reader consumes `motion2scene_timed_schedule_value_v1` artifacts with phase-specific arrays, exact feature/option/request binding, and explicit qualified/trained masks. A currently legal action without a measured trained head is an error. Single-action holds and mandatory qualified returns bypass the learner. Return requests remain visible when a current-state guard refuses them; they never become silent holds or protective stops.

The reusable collector is `scripts/research/motion2scene_collect_timed_schedules.py`:

```sh
.venv_research/bin/python scripts/research/motion2scene_collect_timed_schedules.py prepare \
  --out /absolute/new-registration --registry /absolute/verified-registry.json \
  --request /absolute/qualification-request.json --template /absolute/template-manifest.json \
  --cell neutral --scene-definition /absolute/scene-definition.json \
  --policy-mode forced --seed 8731
.venv_research/bin/python scripts/research/motion2scene_collect_timed_schedules.py run \
  --out /absolute/new-registration
```

An optional `--forced-option-ids neutral` registers only a smoke branch. It never fills missing alternatives with labels. Online modes register one episode; `--preferred-option-id` and `--preferred-reference-id` configure the corresponding baselines. Learned mode requires `--policy` with its SHA bound before execution.

A scene definition has schema `motion2scene_timed_schedule_scene_v1`, an explicit split and scene ID, a SHA-bound native USD, `beams` containing one or two complete transforms/dimensions, and `beam_collision_enabled` with one boolean per beam. Two-beam courses require both constraints enabled. The reserved-evaluation split additionally requires a SHA-bound evaluation protocol; prepare, execution, and analysis each call the reserved-execution validator with actual command, policy, registry, controller, feature order, and source-artifact identities. Proposed or incomplete protocols cannot authorize execution. Optional `--runtime-assets` binds an explicit JSON list of native assets; complete native-asset/environment documentation remains an adoption gate. The collector does not discover or change evaluation layouts. Actual native beam count, length, width, thickness, underside, yaw, center, and `physics:collisionEnabled` are independently audited after import.

Every body-to-beam counterpart is recorded at 200 Hz, including a second beam. Per-body/filter native mappings and complete clock blocks are checked, and the largest normal-force vector per substep block is retained. All-beam forces determine course completion; an unreached second beam remains a failed course. The whole captured horizon additionally requires stability, no undesired environment contact, and the exact entry/return chronology. Internal contact pairs are reported separately under the previously registered environment-contact criterion. Measurements remain admitted when a correctly captured physical passage fails. Mechanical work remains unavailable with the inherited implicit-actuator instrumentation.

`analyze_cell(cell, manifest, bank, scene)` returns `(row, payload, interface)`. Rows include sensor, trajectory, exact feature archive, all-body contacts, environment pair contacts/mapping, alignment masks, all-beam synchronization, per-phase/per-beam visibility audits, schedule audits, and measured success/time. Sensor rows preserve `active_before`, `active`, features, legal mask, and selected complete option. The collector intentionally emits no lookahead teacher: a separate matched-prefix audit must compare all required future schedules before assigning a value to waiting. All attempted failures and available partial captures remain recorded. The separate `outcome` receipt distinguishes verified task failure from unknown physical outcome due to invalid or missing measurements. An observed earlier fall/contact/refusal survives later missing sensor phases; absent later phases remain unavailable for teacher supervision. `task_outcome_admitted` and complete `measurement_admitted` are separate fields. A finite 299-frame native reference yields 298 captured control rows, avoiding the loader's wrap callback; it is never padded for an unfinished course.

Focused tests cover exact 114D behavior, phase-head round trips and missing-head rejection, late constant/scripted commitment, forced return despite a failed neutral guard, preaction timeline corruption, forbidden reentry, explicit beam counterpart registration, altered or disabled second-beam geometry, incomplete courses, second-beam contacts, and subset smoke registration. These are synthetic software tests, not physical qualification evidence.
